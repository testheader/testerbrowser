Session & tab management

Isolated sessions

Every tab is its own Electron session partition, with its own cookies, cache and localStorage. New tabs default to an in-memory partition that's discarded on close; marking a tab persistent (or restoring a closed one) keeps its partition on disk so its data survives a restart. Right-click a tab → New tab in this session opens another tab sharing the same partition — handy for testing multiple pages under one logged-in identity.

Session snapshot

Right-click a tab → Export snapshot… to save that session's cookies, localStorage, sessionStorage and current URL to a JSON file via a save dialog. Import snapshot… restores a previously exported file back into a tab — useful for capturing a specific logged-in/test state and handing it to someone else, or reproducing it later. This is separate from Clone (same menu), which duplicates a tab into a brand-new session and copies its cookies live, without going through a file.

Test data

Right-click any editable form field for a Fill with test data submenu with one-click generators — first/last/full name, email, UUID, today's date, phone, address. Custom template… opens a small input where you can type your own template string to generate more specific values, then inject it straight into the focused field.

Console panel tabs

Console tab

Shows the live console/log portion of the session's always-on recorded timeline — page console.* calls and browser log entries, color-coded by level (error/warn/info/log). Type in the filter box to substring-match log text; click a line with extra payload data to open it in the detail panel. Clear empties the visible buffer.

Storage tab

Live tables of the active session's cookies and localStorage. Cookies show domain/name/value/path/SameSite/expiry/Secure/HttpOnly with a badge distinguishing first- vs third-party, and a domain filter can narrow the list to cookies relevant to the page currently loaded. Double-click any row to edit it inline, click to copy a value, use + Add to create new entries, and × / Clear All to delete.

Security tab

Click Scan session to run a heuristic pass over everything recorded so far: plain-HTTP requests, missing security headers (CSP, X-Frame-Options, X-Content-Type-Options, HSTS, Referrer-Policy) on HTTPS responses, cookies set without Secure/HttpOnly, and 401/403 auth failures. Findings are grouped High/Medium/Low with a filter and severity toggles; clicking one opens the underlying request/response in the detail panel.

Mock tab

Define request-interception rules — a URL glob pattern, an HTTP method (or Any), a fake status code and a response body — then Add rule to apply it immediately to the active session's traffic. Rules track live hit counts and last-hit time, can be toggled on/off, and matched requests show a MOCK badge in the timeline.

Resilience tab

Injects network failure conditions into the active session so you can see how the app under test copes: 500 errors, timeouts (504), offline, 404s, corrupted responses, added latency, or a random-500 chance. Pick a failure type, a URL pattern and a probability %, then Add rule — matched responses get a RESILIENCE badge in the timeline, and each rule tracks how many times it's fired.

A11y tab

Click Refresh to pull the full accessibility tree (role, accessible name, description, states) for the current page into an expandable tree view. Inspect element turns on a live hover/click mode over the page itself — hovering highlights the matching node in the tree, so you can quickly check what role and name a specific element actually exposes.

VR tab (visual regression)

Click Capture baseline to screenshot the current page (the visible viewport, or the whole scrollable page with "Full page" checked). After making a change, click Compare to take a new screenshot and generate a pixel-level diff — differing pixels highlighted, the rest dimmed — plus the percentage of the page that changed. View toggles switch between Baseline / Current / Diff / side-by-side.

Diff tab (network diff)

Pick two open sessions (Session A / Session B) and click Compare to diff their recorded requests by method + URL — same, different status, or only present in one side — in a color-coded table. Once a comparison has run, Export HAR downloads it as a HAR file, which is useful for comparing the same flow across two environments (e.g. staging vs. production).

Spoof tab

Overrides timezone, locale and geolocation for the active session. Pick a city preset to auto-fill sensible values, or enter custom timezone/locale/coordinates, then Apply to session — Reset overrides clears them again. Reload the page afterwards so it picks up the new values.

Jira tab

Configure your Jira URL, email, API token and default project once via the gear icon. Type a ticket key and click Load to see its summary, status, assignee and priority right next to the page under test. + Add Bug opens a form pre-filled from the current tab's URL/title, and Submit Bug files it as a real Jira issue.

Tests tab (record & playback)

Click Start to record real clicks, fills and navigations on the page as a step list — right-click a step to insert assertions (visible, text, URL, wait-for) — then Stop and Save to name the test. Saved tests can be run once, or repeated many times in a row to flag flaky steps, with a pass/fail breakdown per run and an auto-captured screenshot on failure. No AI involved — it's a literal record/replay of the actions you performed.

Productivity tools

HAR export

The HAR button (Console tab toolbar, and in the network-diff view) exports everything recorded for a session as a standard HAR file — for handing off to an external HAR viewer, attaching to a bug report, or archiving a run.

Speed Dial

The new-tab page shows a grid of site tiles with favicons; + Add site adds one by URL and title, and each tile has a × to remove it. Tiles are shared across every session (not tied to one tab's isolated storage), so your frequently-tested environments are always one click away from a fresh tab.

Request replay

Click ↺ Replay on any recorded network request to open it in an editable form — method, URL, headers, cookies and body all pre-filled from the original call. Edit whatever you need to probe (add/remove a header, reformat the body, pull cookies from a different open session), then Send to actually issue the request and see the live response, without going back through the app's UI.
