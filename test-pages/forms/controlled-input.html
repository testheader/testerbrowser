React-style controlled input

Reproduces React's own value-tracking mechanism (inputValueTracking.js) without pulling in React itself: a getter/setter pair is installed directly on the <input> element (an own property, shadowing — not replacing — the accessor on HTMLInputElement.prototype), and an input listener only treats a change as "real" — and updates the text below — when the tracker's last-known value differs from the value actually on the DOM node at event time. Assigning el.value = x goes through the shadowed setter, which updates the tracker in lockstep, so the framework never sees a discrepancy and the "last value seen" text does not move — exactly like a real React-controlled input silently reverting a naively-injected value on its next render. Calling the native prototype's setter directly (bypassing the shadowed property) leaves the tracker stale, so the following input event reads as a genuine external change, the same way real typing does.
